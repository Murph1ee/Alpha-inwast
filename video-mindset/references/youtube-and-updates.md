# อ่าน YouTube และอัปเดตสกิลจากบทเรียน

อ่านเอกสารนี้เมื่อแหล่งข้อมูลเป็น YouTube/ไลฟ์ย้อนหลัง หรือเมื่อผู้ใช้ขอให้นำผลวิเคราะห์มาอัปเดตสกิล ใช้ร่วมกับกติกาหลักฐานใน `SKILL.md`

## เข้าถึงเนื้อหาและตรวจขอบเขต

1. ใช้รหัสวิดีโอเชื่อม URL รูปแบบ `/live/`, `/watch?v=` หรือ `youtu.be/` เพื่อไม่สับสนกับคนละคลิป อ่าน metadata เพื่อระบุชื่อ ผู้เผยแพร่ วันที่ และความยาวเท่าที่มี แต่ไม่ใช้ metadata แทนเนื้อหา
2. ตรวจคำบรรยายที่ผู้สร้างจัดทำก่อนเมื่อมี เลือกภาษาต้นฉบับที่เหมาะกับงาน หากใช้คำบรรยายอัตโนมัติหรือคำแปลให้ระบุชนิดนั้น ไม่สมมติว่าทุกคลิปเป็นภาษาไทย แยก `live_chat` และความคิดเห็นออกจากคำพูดในคลิป
3. ใช้เครื่องมือที่มีเพื่ออ่านคำบรรยายหรือแผง transcript หากช่องทางแรกไม่ได้ ให้ลองช่องทางอื่นที่มีเหตุผลว่าจะได้เนื้อหา การดึงข้อมูลล้มเหลวไม่ได้พิสูจน์ว่าคลิปไม่มีคำบรรยาย เมื่อไม่มีช่องทางที่ใช้ได้ให้ขอ transcript หรือช่วงเหตุผลที่จำเป็น ไม่วนลองวิธีเดิมโดยไม่มีข้อมูลใหม่
4. เก็บไฟล์ดิบและ metadata ที่จำเป็นไว้ในพื้นที่ทำงาน แยกจากบันทึกบทเรียนที่ติดตั้งในสกิล เก็บลิงก์วิดีโอต้นทางเป็นแหล่งอ้างอิงถาวร ไม่เก็บ URL คำบรรยายที่มีลายเซ็นหรือวันหมดอายุเป็นลิงก์หลักในสกิล

### ตัวเลือกเมื่อมี yt-dlp

ตัวอย่างต่อไปนี้ใช้ดึงคำบรรยายอัตโนมัติภาษาไทยพร้อม metadata โดยไม่ดาวน์โหลดวิดีโอ เป็นตัวเลือกที่ได้ทดสอบกับคลิปหนึ่งแล้ว ไม่ใช่ข้อรับรองว่าใช้ได้กับทุกคลิป:

```text
yt-dlp --skip-download --write-auto-subs --sub-langs th --sub-format json3 --write-info-json -o 'work/video-mindset/%(id)s.%(ext)s' '<URL>'
```

- ใช้ `--list-subs` เพื่อตรวจภาษาและชนิดคำบรรยายเมื่อจำเป็น หากมีคำบรรยายที่ผู้สร้างจัดทำ ให้เลือกชนิดนั้นด้วย `--write-subs`; เปลี่ยน `th` ให้ตรงภาษาที่ต้องการ
- แทน `<URL>` ด้วยลิงก์คลิปจริง และเลือกพื้นที่ทำงานที่เขียนได้ตามสิทธิ์ปัจจุบัน ตรวจผลลัพธ์จริงก่อนอ้างว่าดึงคำบรรยายสำเร็จ ไม่เปลี่ยนการตั้งค่าหรือใช้ข้อมูลเข้าสู่ระบบเพิ่มเพียงเพราะตัวอย่างนี้มีคำสั่ง
- หากไม่มีเครื่องมือหรือคำสั่งล้มเหลว ใช้ช่องทางที่มีแทนได้ อย่าทำให้การติดตั้งเครื่องมือเป็นเงื่อนไขบังคับของการวิเคราะห์

## อ่านคลิปยาวโดยรักษาหลักฐาน

- แปลงคำบรรยายเป็นข้อความที่มีตำแหน่งเวลา โดยเก็บไฟล์ต้นฉบับไว้ ใน JSON3 ใช้ `tStartMs` ของรายการและข้อความใน `segs` ตามที่มีจริง ข้ามรายการที่ไม่มีข้อความ อย่าสร้างเวลาใหม่จากความยาวข้อความ
- คำบรรยายเลื่อนอาจมีข้อความซ้ำ ลบเฉพาะส่วนซ้ำที่ตรวจได้โดยรักษาคำปฏิเสธ เงื่อนไข และความต่อเนื่องของผู้พูด ห้ามแก้คำที่ไม่แน่ใจแบบเงียบ ๆ โดยเฉพาะชื่อหุ้นและตัวเลข
- แบ่งอ่านตามหัวข้อหรือช่วงเวลา พร้อมบันทึกช่วงที่อ่านแล้ว ช่วงที่ขาด และตำแหน่งสุดท้ายของคำบรรยาย เทียบกับความยาววิดีโอเมื่อทราบ การมีไฟล์คำบรรยายไม่ได้ยืนยันว่าครบทั้งคลิป
- ก่อนสรุปแต่ละเทคนิค ให้อ่านบริบทก่อนและหลัง รวมข้อยกเว้นหรือคำพูดที่ขัดกัน การค้นเฉพาะคำหรืออ่านเฉพาะช่วงต้องรายงานว่าเป็นการวิเคราะห์บางส่วน
- หากแบ่งเสียงเป็นไฟล์ย่อย ต้องรู้จุดเริ่มของไฟล์ก่อนแปลงเวลาในไฟล์ย่อยเป็นเวลาของคลิปต้นฉบับ ระบุว่าเป็นเวลาจากการถอดเสียง การอ่าน timestamp ไม่ได้แปลว่าได้ตรวจเสียงหรือวิดีโอแล้ว
- ในผลลัพธ์ให้บอกว่าอ่านคำบรรยายหรือได้ตรวจสื่อจริง ช่วงที่ครอบคลุม และจุดที่ยังยืนยันไม่ได้ อย่าใช้คำว่า “ดูทั้งคลิปแล้ว” เมื่อเข้าถึงเพียงข้อความ

## เมื่อผู้ใช้ขออัปเดตสกิล

แยกผลวิเคราะห์คลิปกับการเปลี่ยนสกิลให้ตรวจได้ โดยใช้การอนุญาตและขอบเขตงานที่ผู้ใช้ให้ไว้ การอ่านคลิปอย่างเดียวไม่ใช่คำขอให้แก้สกิลโดยอัตโนมัติ

- ปรับ `SKILL.md` เฉพาะวิธีทำงานที่ใช้ซ้ำได้ ไม่ใส่ชื่อหุ้น ราคา หรือความเชื่อของผู้พูดคนหนึ่งเป็นเกณฑ์บังคับสำหรับทุกคลิป
- เมื่อมีบทเรียนเฉพาะคลิปที่มีหลักฐานและควรเก็บใช้ต่อ ให้บันทึกสรุปใน `references/videos/<video-id>.md` พร้อมลิงก์ต้นทาง ผู้พูดเท่าที่ทราบ วันที่เผยแพร่และวันที่ข้อมูล ขอบเขตที่อ่าน ชนิดหลักฐาน ตำแหน่งอ้างอิง เทคนิค เงื่อนไขใช้ และข้อจำกัด แยกสิ่งที่ผู้พูดกล่าวจากการตีความและข้อเสนอของผู้วิเคราะห์ ไม่เก็บ transcript ทั้งคลิปเป็นฐานความรู้ของสกิล
- เชื่อมบันทึกที่สร้างจริงจาก `SKILL.md` หรือดัชนีที่มีอยู่ พร้อมบอกให้อ่านเมื่อคลิปหรือเทคนิคนั้นเกี่ยวข้อง ไม่สร้างแฟ้มหรือดัชนีเปล่าล่วงหน้า และไม่โหลดทุกคลิปในทุกงาน
- ใช้รหัสวิดีโอป้องกันรายการซ้ำ หากเพิ่มหลักฐานของคลิปเดิมให้แก้บันทึกเดิม รักษาข้อขัดแย้งและความไม่แน่นอน อย่านำผลจากคลิปหนึ่งไปยืนยันว่าผู้พูดคิดเช่นนั้นเสมอหรือวิธีนั้นได้ผลทั่วไป
- หากเข้าถึงเนื้อหาไม่ได้ ยังปรับกระบวนการจากปัญหาที่พบจริงได้ แต่ห้ามบันทึกบทเรียนลงทุนที่คาดเดา รายงานว่าการวิเคราะห์หรือการสะสมความรู้ส่วนใดยังต้องรอเนื้อหา
- เตรียมและตรวจไฟล์ที่เปลี่ยนก่อนติดตั้ง รักษาไฟล์และ metadata ที่ไม่เกี่ยวข้อง การขอให้อัปเดตสกิลไม่ได้ยกเลิกข้อจำกัดสิทธิ์เขียนของสภาพแวดล้อม
- ตรวจเนื้อหา diff และลิงก์อ้างอิงจริง รวมถึงตัวตรวจรูปแบบสกิลเมื่อมี แล้วรายงานแยกให้ชัดว่าเตรียมฉบับปรับแล้วหรือติดตั้งสำเร็จแล้ว อย่ารายงานว่าสกิลที่ติดตั้งเปลี่ยนไปหากมีเพียงไฟล์สำเนา
